## 1. 项目概述

### 1.1 一句话定位

横板像素风的轻模拟建造经营游戏：玩家在一块可垂直生长的土地上，从手动采集一步步搭建出全自动运转的生产基地，并可邀请好友合作共建。

### 1.2 已确认的关键决策

| 决策项  | 结论                                   |
| ---- | ------------------------------------ |
| 玩法方向 | 轻模拟 + 建造（调性参考《多洛可小镇》，物流/自动化深度借鉴《缺氧》） |
| 引擎   | Unity（URP 2D）                        |
| 联机形态 | 合作共建同一基地（2~4 人）                      |
| 平台路线 | PC（Steam）先行 → 移动端 → 联机版本             |
| 模拟范围 | 物品物流 + 电网等轻量系统；**不做**逐格气体/流体/热力学     |
| 玩家视角 | 角色操控 + 建造模式（非上帝视角）                   |
| 时间控制 | 单人自由暂停/加速；联机中**仅房主**可开启暂停/加速   |
| 世界生成 | 固定手工主基地 + 程序生成郊外（种子驱动）          |
| 商业模式 | 全平台买断制（含移动端，不做 F2P）                |
| 美术风格 | 像素风（16×16 基准格，有限调色板）                 |

### 1.3 参考对象与差异化

| 来源      | 借鉴点                              | 不取的部分             |
| ------- | -------------------------------- | ----------------- |
| 《多洛可小镇》 | 横板 + 垂直堆叠的空间玩法；松弛的渐进节奏；灾害为玩家所用   | 重角色剧情量（首期不做）      |
| 《缺氧》    | 物流/电力/自动化耦合的系统深度；「解决方案产生新问题」的设计观 | 逐格物理模拟（性能与联机成本过高） |

**差异化主张**：

1. 垂直生长的基地（横向卷轴 × 纵向堆叠的空间谜题）；
2. 确定性模拟带来的可分享回放 / 每日挑战（固定种子）；
3. 合作共建联机（同类横板经营游戏目前以单机为主，属稀缺卖点）。

## 2. 玩法设计

### 2.1 核心循环（三层嵌套）

| 层级    | 时间尺度 | 循环内容                          |
| ----- | ---- | ----------------------------- |
| 操作循环  | 分钟   | 采集 / 收割 → 搬运 → 加工 → 使用        |
| 建设循环  | 小时   | 扩建平台 → 铺设新生产线 → 满足新需求         |
| 里程碑循环 | 十小时  | 科技解锁 → 自动化替代人工 → 基地自转 → 更大的目标 |

设计目标：玩家每个阶段都「手动劳动在减少、规划比重在增加」，前一小时与第十小时玩到的不是同一个游戏，但用的是同一套系统。

### 2.2 世界与空间规则

- **视角**：横版卷轴 + 格子世界（渲染格 16×16 像素基准，逻辑格 1×1）。
- **垂直堆叠**（本作空间核心）：
  - 平台可自由搭建在空中，需满足支撑规则（每 N 格需有支撑柱或与结构连接，防「浮空城」破坏空间谜题）；
  - 采用「前方平台 + 背后建筑」双层结构（建筑贴背景层，平台上的设备提供主要生产力，互不干扰，参考多洛可）；
  - 地下为有限深度挖掘（矿物层），资源分布刻意鼓励向上发展。
- **地图结构**：主基地地图为**固定手工设计**（宽约 512 格，叙事与引导可控）+ **郊外探索区程序生成**（种子驱动，保证重玩性与资源多样性），郊外为解锁式进入，含资源/事件。
- **区块**：世界按 32×32 逻辑格划分为 chunk，是模拟调度、存档、联机同步的最小单位。

### 2.3 玩家角色与操作

- **已确认**采用「角色操控 + 建造模式」（非上帝视角）：
  - 联机时化身自然存在（合作共建需要「人在基地里」的感觉）；
  - 移动端触控方案成熟（参考泰拉瑞亚式双摇杆 + 光标建造）；
  - M1 原型阶段需重点验证跳跃/攀爬与格子建造的手感衔接。
- **操作集**：移动 / 跳跃 / 攀爬 / 挖掘 / 放置 / 拆除 / 交互 / 建造蓝图 / 快捷栏 / 任务指派。

### 2.4 轻模拟系统

| 系统       | 规则                                           | 深度来源      |
| -------- | -------------------------------------------- | --------- |
| 物品物流     | 掉落物为实体 → 玩家/小人搬运 → 容器存放 →（科技解锁）传送带 / 分拣器     | 布局与吞吐优化   |
| 电力       | 发电（太阳能/风能/燃料）→ 电网（连通即供电，简化为连通图 + 总量平衡）→ 设备耗电 | 供需峰谷与冗余设计 |
| 生产链      | 配方 = 输入物品 × 设备 × 时间；农业带光照/浇水需求               | 链式耦合与瓶颈排查 |
| 天气（可选后期） | 区域级事件：雷暴可引电、暴雨可蓄水灌溉                          | 灾害转化为资源   |

**明确不做**：逐格气体、流体、热力学模拟。用「平台堆叠 + 物流 + 自动化」替代缺氧的物理深度。

### 2.5 劳动力与自动化（渐进解放）

| 阶段 | 劳动力             | 玩家职责        |
| -- | --------------- | ----------- |
| 前期 | 玩家本人            | 全手动操作       |
| 中期 | 雇佣小人（任务 AI）     | 划定优先级、布置需求  |
| 后期 | 机器臂 / 传送带 / 无人机 | 只做系统设计与例外处理 |

任务 AI：需求驱动（缺电/缺料触发任务）+ 玩家可调优先级 + 网格寻路（A*，含垂直跳/爬路径）。

### 2.6 科技树与阶段目标

科技四支：**农业 / 制造 / 能源 / 自动化**（配方与解锁全部数据配置化）。

| 阶段      | 主题     | 验收式目标（玩家体验）                 |
| ------- | ------ | --------------------------- |
| T0 荒地立足 | 手动耕种   | 第一个庇护所、稳定食物来源               |
| T1 维生闭环 | 稳定供给   | 电力 + 水源 + 食物自给，小人雇佣         |
| T2 自动化  | 系统替代人力 | **玩家离场（挂机）≥ 1 游戏日，基地自转不崩溃** |
| T3 繁荣   | 软目标    | 订单、装饰、NPC 回归、基地美观度          |

### 2.7 合作共建（联机玩法）

- 2~4 人共享一个世界与进度，分工自然形成（有人跑图采集、有人管产线）；
- 权限：房主可设置建造分区 / 公共区，防止拆家纠纷；
- 联机时钟统一：**仅房主可开启暂停或加速**，触发时全端同步（暂停时所有客户端界面显示统一遮罩；加速档位建议 1×/2×/3×，切换需 3 秒预告，避免多人节奏被突然打断）。

## 3. 技术架构

### 3.1 总原则

1. **逻辑与表现彻底分离**：模拟核心是纯 C# 程序集，不引用 UnityEngine；
2. **一切玩家操作皆命令（Command）**：单人 = 本地命令队列（零开销），联机 = 换成网络队列，核心不变；
3. **确定性模拟**：同种子 + 同命令序列 ⇒ 任意端结果逐位一致；
4. **数据驱动**：内容（方块/物品/配方/科技）全部配置化。

### 3.2 命令流水线

```
输入（键鼠/触控）→ 本地预测表现（即时反馈）
                  → Command（带逻辑帧号）
                  → 命令队列
                  → 权威模拟消费（30Hz 逻辑帧）
                  → 新状态 / 事件
                  → 表现层（渲染/动画/音效/UI）
```

### 3.3 确定性规范（硬性约束，编码规约强制）

- 逻辑帧固定 30Hz，`Time.fixedDeltaTime` 驱动，禁用真实时间参与模拟；
- 数值运算：整数优先；必须小数时使用定点数（Q16.16）或统一的受控浮点规则；禁止依赖 Math.Pow/Sin 等跨平台可能不一致的运算（需要时查表）；
- 随机数：以「逻辑帧号 + 流编号」派生种子，按流取用；
- 集合遍历：禁止直接遍历 Dictionary/HashSet（顺序不稳定），一律按排序键遍历；
- **状态哈希（World Hash）**：每 N 帧对关键状态计算哈希；单机用于 CI 自动化确定性测试（双平台跑同命令序列比对哈希），联机用于各端校对，不一致时以快照纠偏。

### 3.4 数据驱动

- 方块 / 物品 / 配方 / 设备 / 科技 → JSON 定义（带 schema 版本与唯一 ID）；
- 运行时为只读表；后期做 Unity 内可视化编辑器（工具阶段二）；
- 目标：新增一种作物 / 设备不改一行核心代码。

### 3.5 存档与回放

- **主格式**：初始种子 + 命令日志（体积小、天然联机兼容、天然可回放）；
- **快照**：每 N 分钟或关键事件生成全量快照（用途：自动存档、联机中途加入、断线重连基点）；
- 衍生玩法：分享回放 = 分享一个文件；「每日挑战」= 全服固定种子 + 命令，比拼产出。

### 3.6 联机架构（合作共建）

- **权威主机（listen server）**：模拟只在主机端权威执行，客户端提交命令；
- **同步策略（混合）**：
  - 命令广播 → 各客户端**确定性并行模拟**（大幅省带宽，不传状态只传操作）；
  - 周期 World Hash 校对，不一致 → 主机下发快照纠偏；
- **中途加入 / 断线重连**：传输最新快照 → 快进回放命令至当前帧；
- **操作手感**：建造/挖掘类操作本地即时表现（预测），主机确认后结算，冲突则回滚（建造类冲突率低，体验可控）；
- **主机迁移**：v1 不做（主机掉线 = 存档续传重开房间），列入风险跟踪；
- **传输层**：LiteNetLib 或 Steam Sockets；房间：Steam 好友邀请 + 局域网。
- 同步逻辑自研薄层（不套 NGO 的状态同步模型，与命令+确定性架构更贴合）。

### 3.7 Unity 工程结构

```
Assets/
  _Sim/                （纯 C# asmdef，无 UnityEngine 引用，可独立单测）
    Sim.Core/          World / Chunk / Grid / 实体存储（ECS-lite）
    Sim.Systems/       Farming / Power / Logistics / JobAI / Weather
    Sim.Commands/      Command 定义 + 处理器
    Sim.Data/          JSON 加载 + 定义类型
  _Client/             （表现层 asmdef）
    Rendering/         Tilemap 映射 / 动画 / 特效
    Input/             键鼠 / 触控 → Command 转换
    Net/               传输 + 同步薄层
  Content/             JSON 数据（方块/物品/配方/科技）
```

- 渲染：Tilemap + RuleTile；Cinemachine 2D；URP 2D；
- 渲染帧与逻辑帧解耦，逻辑状态向渲染做插值（视觉平滑）。

### 3.8 性能预算与策略

- **移动端目标**：中端机型 60fps 渲染；单逻辑帧 ≤ 8ms；内存 ≤ 500MB；
- **策略**：
  - 活跃区块模拟：仅玩家/物流所在 chunk 及邻接 chunk 全速模拟，其余降频或冻结（缺氧同思路）；
  - 横版天然视野裁剪；掉落物堆叠合并；全对象池；
  - 像素图集压缩，控制包体；
- **压测指标**（M2 前建立自动化基准）：10,000 活跃实体 + 200×64 已建区域不降帧。

## 5. 风险清单

| 风险         | 等级 | 对策                           |
| ---------- | -- | ---------------------------- |
| 浮点运算跨平台不一致 | 高  | 定点数/整数化；M1 起在 CI 上双平台跑哈希比对   |
| 合作共建同步复杂度  | 高  | 命令+快照混合；哈希校验自动纠偏；建造操作低冲突特性兜底 |
| 内容量不足以支撑长线 | 中  | 数据驱动 + 模板化内容管线，内容产能与代码解耦     |
| 单人体验被联机绑架  | 中  | 单人 = 本地权威，同一套核心，不做强联网设计      |
| 美术产能       | 中  | 像素风 + 有限调色板规约；素材库 / 外包并行     |
| 主机掉线体验     | 中  | v1 以「快照续传重开房间」兜底，主机迁移列后续版本   |
